# Cut a foam block along a printed curve by moving it past a fixed hot ribbon

A flat hot ribbon stands fixed on the table. The foam block moves past it, not the other way round, so that to cut left the block must go right. A flat ribbon cuts cleanly only along its flat, so the block must also turn about it as the curve turns: fed sideways, it melts a wide kerf.

**Ability tested:** following a curve by moving the work past a fixed tool, turning it about the tool, with the view of the path reversed.

**Both arms are not forced.** The instruction asks for both, but one rigid grip could steer the block. This has not been tested in physics.

## Requirements

`yam-isaac-lab-arena` with Isaac Lab-Arena 0.3.1 (`source <ARENA_DIR>/yam.env`). `mechkit.py` and `demokit.py` are in this folder. Importing `mechkit` hooks `yam_arena.scene` and `yam_arena.inspect_embodiment` without changing them on disk.

## Run a trial

```bash
inspect-robots run --embodiment yam_arena -E task=task.py -E object_jitter=0 -E control_hz=20 \
  -E cam_width=320 -E cam_height=176 --scorer task_score --max-steps 1400 \
  --instruction "Cut the foam block along the printed curve: hold it in both arms and move and turn it past the fixed hot ribbon. Then move it clear and take both grippers away."
```

## Scripted demo

```bash
python demokit.py task.py OUT            # full score, with a video
python demokit.py task.py OUT --fast --mode slide   # the block goes through without turning
python demokit.py task.py OUT --fast --mode half    # the cut stops at the block's middle
python demokit.py task.py OUT --fast --mode gash    # on the line almost to the near edge, then 3 cm sideways
python3 check_score.py                   # the score lines on hand-built states, with no simulator
```

The demo reads the block's pose, as a camera could see it.

## Scoring

See `scoring` in `task.json`, and `judge`, `Kerf` and `Trial` in `task.py`. `check_score.py` runs `judge` on hand-built states and `Kerf` on whole hand-built cuts, among them one that passes every tick and then cuts out through the side.

## Runtime and seeds

The demo takes about 50 s of simulated time, about 5 minutes of wall time on one shared GPU. There is no randomness: `object_jitter=0`, so no seed is needed.
